# StepSearch (arXiv:2505.15107v2, 26 May 2025) — implementation fragment

**Paper:** *StepSearch: Igniting LLMs Search Ability via Step-Wise Proximal Policy Optimization* (Wang, Zheng, An, et al., SenseTime). Code (promised): https://github.com/Zillwang/StepSearch

The method is called **StePPO** = vanilla actor–critic **PPO** (with learned value function, GAE, KL-to-reference) augmented with (a) a global "search-key" reward added to the answer reward, and (b) per-search-round token-level step rewards (information gain − redundancy penalty). Rollout format is Search-R1-style `<think>` / `<search>` / `<information>` / `<answer>` loops; retrieved `<information>` tokens are loss-masked.

---

## 1. Rewards — exact equations (numbering as in the paper)

### 1.0 PPO objective (Eq. 1)

For sample input x ~ D, output o from old policy π_{θ_old}; I(o_t) is the token-loss masking indicator: I(o_t)=1 if token o_t was generated by the actor LLM, else 0 for retrieved (`<information>`) tokens. Policy π_θ optimized with reference policy π_{θ_ref}:

$$
\mathcal{J}_{\text{StePPO}}(\theta) = \mathbb{E}_{x\sim\mathcal{D},\,o\sim\pi_{\theta_{old}}(\cdot|x)}
\left\{ \frac{1}{\sum_{t=1}^{|o|} I(o_t)} \sum_{t=1:I(o_t)=1}^{|o|}
\left[ \frac{\pi_\theta(o_t|x,o_{<t})}{\pi_{\theta_{old}}(o_t|x,o_{<t})} A_t,\ 
\text{clip}\!\left( \frac{\pi_\theta(o_t|x,o_{<t})}{\pi_{\theta_{old}}(o_t|x,o_{<t})},\, 1-\epsilon,\, 1+\epsilon \right) A_t \right] \right\}
\tag{1}
$$

(min over the two bracketed terms, standard PPO-clip; ε is the clip hyper-parameter.) A_t is the advantage from **GAE** [Schulman et al. 2015], computed from future rewards r_{≥t} — composed of the **global** reward and the **step-wise search-round** rewards — and a learned value function V_φ. **Reward placement: the global reward is set at the last position of the output; the step-wise reward is set at the last token of each round of search behaviour.** Note the loss is normalized by the number of *unmasked* (actor-generated) tokens, 1/Σ I(o_t).

### 1.1 Type 1 Reward: Global signal (sequence-final token)

**Format requirement** — enforced as a *hard constraint* (format validation), NOT as an explicit reward term:
- Only search queries inside proper `<search>...</search>` pairs are extracted and used to call the search tool; the answer must be in `<answer>...</answer>`.
- At least one round of "think" and "search" behaviour.
- Exactly one `<answer>...</answer>` tag pair, and it must be at the end.

**Answer reward** — word-level F1 between prediction and ground truth. PN = word count of predicted answer, RN = word count of golden answer, IN = word count of their intersection:

$$
\text{F1}(x,y) = \frac{2 * IN}{PN + RN} \tag{2}
$$

$$
r_{\text{answer}} = \begin{cases} \text{F1}(a_{\text{pred}}, a_{\text{gt}}), & \text{format is correct,} \\ 0, & \text{format is incorrect.} \end{cases} \tag{3}
$$

**Search-keys reward** — word-level F1 token overlap between each emitted query and the reference keywords of its corresponding subtask; granted **only when the model's search emission conforms to the required format**. Suppose T rounds of queries Q = {q_1, q_2, ..., q_T}, and M subquestions each with N_i golden queries K_i = {k_{i1}, k_{i2}, ..., k_{iN_i}}, i = 1,...,M:

$$
f_{ijt} = \text{F1}(q_t, k_{ij}), \tag{4}
$$

$$
r_{\text{key}} = \frac{1}{M} \sum_{i=1}^{M} \left( \max_{1\le j\le N_i} \left( \max_{1\le t\le T} f_{ijt} \right) \right)
= \frac{1}{M} \sum_{i=1}^{M} \max_{1\le j\le N_i} \max_{1\le t\le T} f_{ijt}. \tag{5}
$$

I.e., for each golden subquestion i, take the best F1 achieved by *any* emitted query against *any* of its reference keyword-queries, then average over subquestions. (Matching is soft lexical F1 — no exact key lookup.)

**Combination (Type 1 Reward), with scale factor γ_key:**

$$
r_{\text{overall}} = r_{\text{answer}} + \gamma_{\text{key}} \cdot r_{\text{key}}. \tag{6}
$$

> ⚠ **The paper never gives a numeric value for γ_key** (verified by full-text search). It must be taken from the released code.

### 1.2 Type 2 Reward: Search step (per-round, at last token of each search round)

$$
r_{\text{step}}^{t} = \mathcal{G}^{t} - \mathcal{P}^{t}. \tag{7}
$$

**Information gain G^t.** Let D^g = {d_1^g, ..., d_n^g} be the n ground-truth ("golden") documents required to resolve problem p (each d_i^g holds the gold-standard information for one subtask — these come from the MuSiQue decomposition annotations). Maintain a per-episode **memory vector** M^t = [m_1^t, ..., m_n^t], where m_i^t records the maximum similarity observed *to date* between any retrieved document and d_i^g; initialize m_i^0 = 0. At turn t the agent retrieves D^{r(t)} = {d_1^{r(t)}, ..., d_k^{r(t)}} of k documents. Similarity is a submodular coverage function instantiated as **cosine similarity over TF–IDF representations** (naturally enforces diminishing returns / penalizes redundant retrievals):

$$
c_i^t = \max_{1\le j\le k} \frac{\vec{d_i^g} \cdot \vec{d_j^{r(t)}}}{\lVert \vec{d_i^g} \rVert \cdot \lVert \vec{d_j^{r(t)}} \rVert}, \quad i = 1,\cdots,n. \tag{8}
$$

Per-golden-document gain vs. previous global maximum matching degree:

$$
\triangle_i^t = \max(c_i^t - m_i^t,\, 0), \quad i = 1,\cdots,n, \tag{9}
$$

(the m_i^t in Eq. 9 is the memory value carried from the previous round, i.e. m_i^{t-1} before the Eq. 11 update). Round-level gain = average over the n golden documents:

$$
\mathcal{G}^t = \frac{1}{n}\sum_{i=1}^{n} \triangle_i^t = \frac{1}{n}\sum_{i=1}^{n} \max(c_i^t - m_i^t,\, 0). \tag{10}
$$

Memory update after the round (for the next round's evaluation):

$$
m_i^t = max(m_i^{t-1}, c_i^t), \quad i = 1,\cdots,n. \tag{11}
$$

**Redundancy penalty P^t.** Track a per-episode **cumulative retrieval history** H^t (a set of seen documents), H^0 = ∅; each round's retrieved set is I^t. At the end of round t:

$$
H^t = H^{t-1} \cup I^t, \tag{12}
$$

and the penalty is the fraction of this round's retrieved documents D^{r(t)} already seen in any previous round:

$$
\mathcal{P}^t = \frac{1}{k} \sum_{j=1}^{k} \mathbb{1}(d_j^{r(t)} \in H^{t-1}), \tag{13}
$$

where **1**(·) is the indicator function. (Doc identity here is set membership of retrieved documents — exact repeats, cf. Fig. 2 where re-retrieved docs get −1.00 each and a needed new doc gets +0.50.)

**Per-episode state to keep:** memory vector M^t = [m_1^t,...,m_n^t] (max TF-IDF-cosine sim per golden doc, init 0) + seen-documents set H^t (init ∅). No seen-*queries* set is used — query quality is handled globally by r_key.

**How step and outcome rewards combine:** there is **no extra weight between r_step^t and r_overall** in the paper — r_overall (Eq. 6, which internally weights r_key by γ_key) is placed at the final output token, and r_step^t (Eq. 7, unweighted G^t − P^t) at the last token of each search round; GAE then propagates both through A_t. No reward normalization/whitening is described beyond the token-count normalization in Eq. 1.

## 2. Data construction / annotation pipeline (§2.1, Fig. 3)

Base dataset: **MuSiQue** (multi-hop QA with question decompositions). Pipeline:

- **(a)** Leverage **GPT-4o** to enrich decomposed MuSiQue questions with coherent **subquestion–answer pairs**, then derive **N search queries per step** for retrieval. (Value of N not stated.)
- **(b)** Each enhanced step question is reformulated into a set of **N search queries** to facilitate information retrieval.
- **(c)** **Filtering:** queries are issued to **M sources** (e.g., Google, Bing, Wiki-18), and only those returning valid results in at least **⌈M/2⌉ sources** are retained. (Value of M not stated; three engines are named.)

Yields: **60k filtered sub-question search keywords**; final training set is **19k** MuSiQue training samples ("using only 19k training data", ≈11% of the data volume Search-R1 uses, and the custom retrieval corpus is ≈0.35% the size of wiki-18). Training retrieval corpus = their **synthesized (MuSiQue-based) corpus** with **E5** as retriever; for evaluation the corpus is augmented with the **2018 Wikipedia dump** (wiki-18, as in Search-R1). Evaluation datasets: full HotpotQA, 2WikiMultiHopQA, MuSiQue, Bamboogle test/validation sets (EM + word-level F1; no LLM judges).

Prompt templates (Appendix A):
- **Table 4 (main)**: "deep AI research assistant" prompt; output either `<think>...</think> <answer>...</answer>` or `<think>...</think>` + `<search>keywords</search>`; engine returns results in `<information>...</information>`; loop think→search→information→think until solved; includes a worked mini-example `(Q1) (Q2) (Q3)` planning style. Zero-shot (3 CoT demonstration pairs mentioned in §2.2 wording: "a minimalist prompt template comprising three chain-of-thought demonstration pairs plus a dedicated label for retrieved results").
- **Table 5 (sub-answer variant, 'ow sub-answer' ablation)**: adds explicit `<sub_question1>...</sub_question1>`, `<sub_answer1>...</sub_answer1>` tags; intermediate sub-answers were also tried as process feedback in the global reward — helps (Table 3 last row: 3B 'ow sub-answer' HotpotQA EM 0.339), because "keywords in the supervised search behavior process are similar to the sub-question answers".

## 5. Implementation-relevant notes

1. **Vehicle = actor–critic PPO (with critic), not GRPO.** Objective Eq. (1) is token-level PPO-clip with a reference policy for KL (β=1e-3, applied as KL regularization — the paper says "KL-divergence regularization coefficient β"). GAE advantages from a learned V_φ. Their own comparison (Table 2, Fig. 5): StePPO > PPO > GRPO; GRPO was "prone to reward collapse at higher learning rates."
2. **Reward injection points:** global r_overall = r_answer + γ_key·r_key at the *last token of the whole output*; step reward r_step^t = G^t − P^t at the *last token of each search round* (i.e., end of the `</search>` emission for turn t, per Fig. 4 the "Search Step Reward ... applied to tokens within each round"). GAE then spreads credit backward.
3. **Loss masking:** all `<information>...</information>` (retrieved) tokens excluded from gradient via I(o_t); Eq. (1) normalizes by the count of unmasked tokens only. Retrieved content is also masked in Fig. 4 ("masked").
4. **Normalization:** the only normalizations present are (i) 1/n averaging in G^t, (ii) 1/k averaging in P^t, (iii) 1/M averaging in r_key, and (iv) token-count normalization in the PPO loss. No reward whitening/std normalization is mentioned.
5. **Similarity backends:** golden-document matching = cosine over **TF-IDF** vectors (not the E5 embedder); query-to-keyword matching = **word-level F1** overlap. Golden docs d_i^g and golden query sets K_i come from the GPT-4o-augmented MuSiQue annotations (one golden doc per subtask hop).
6. **Format is a gate, not a reward:** malformed output ⇒ r_answer = 0 and r_key withheld; format itself contributes no positive reward. Cautionary result (Appendix C, Table 8): using the *global search-key score as the only process reward* caused reward hacking — the model emitted fake `<search>` actions and fabricated `<information>` — and crashed training. The fine-grained token-level step reward (ow-ss) is what is stable.
7. **Ablation vocabulary** (Table 3 / Fig. 6): `w/o` = without, `ow` = only-with; `rp` = redundancy penalty, `ig` = information gain, `ss` = step score (ig + rp), `skr` = global search-key reward. Findings: redundancy penalty alone does not improve search ability; skr speeds convergence but alone risks hallucination/collapse; ss gives the stable gains; on 7B, w/o key reward is even slightly better on HotpotQA/2Wiki (0.404/0.388 EM) — γ_key sensitivity worth tuning.
8. **Headline results** (for sanity-checking a re-implementation, wiki-18 eval, EM): Qwen2.5-3B-Base StePPO: HotpotQA 0.329, 2Wiki 0.339, MuSiQue 0.181, Bamboogle 0.328; Qwen2.5-7B-Base: 0.380 / 0.385 / 0.216 / 0.467. Gains over the best search-RL baseline: +5.7/+9.1/+10.0/+15.2 abs points; +11.2% (3B) and +4.2% (7B) average over search-RL baselines.
